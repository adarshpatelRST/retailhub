### B. `InventoryService` (`inventory.service.ts`)
Implement the following methods:
1. `findAll(query: InventoryQueryDto, dataScope?: any)`:
   - Merges query with `dataScope` constraints (Store Managers only see their store).
   - Joins `product` (with brand/category) and `store`.
   - Computes stock status dynamically:
     - `availableQuantity <= 0` -> `CRITICAL`
     - `availableQuantity <= reorderLevel` -> `LOW`
     - `availableQuantity > maximumStock` -> `EXCESS`
     - Otherwise -> `HEALTHY`
   - Returns `PaginatedResponse<Inventory>`.
2. `getBalance(storeId: string, productId: string)`:
   - Fetches balance including `availableQuantity`, `reservedQuantity`, `inTransitQuantity`, `version`.
   - If not found, lazily creates and returns a zero balance row.
3. `adjustStock(dto: AdjustStockDto, userId: string)`:
   - Executes inside `prisma.$transaction`.
   - Verifies optimistic lock: checks if existing row has `version === dto.expectedVersion`. If not, throws `ConflictException('INV_CONCURRENCY_CONFLICT')`.
   - Calculates new `availableQuantity = availableQuantity + quantityDelta`. If new balance < 0, throws `BadRequestException('INV_INSUFFICIENT_STOCK')`.
   - Updates `availableQuantity` and increments `version = version + 1`.
   - Inserts `InventoryMovement` with `movementType: dto.quantityDelta > 0 ? 'STOCK_ADJUSTMENT' : 'DAMAGED_WRITE_OFF'`, `referenceType: 'MANUAL_ADJUSTMENT'`, `quantity: dto.quantityDelta`, `createdBy: userId`.
4. `getMovements(storeId: string, productId: string, page = 1, limit = 50)`:
   - Returns paginated history from `InventoryMovement` sorted by `movementDate DESC`.
5. `saveRule(dto: InventoryRuleDto)`:
   - Creates a new `InventoryRule` row enforcing effective-date versioning (SCD Type 2). If an active rule exists, sets its `effectiveTo = now()` before inserting the new rule.

### C. `TransferService` (`transfer.service.ts`)
Implement the complete transfer state machine inside atomic transactions:
1. `createTransfer(dto: CreateTransferDto, userId: string)`:
   - Generates unique `transferNumber` (e.g. `TRF-${Date.now().toString().slice(-6)}`).
   - Inserts `StockTransfer` with `status: 'PENDING_APPROVAL'` and child `StockTransferLine`s.
2. `dispatchTransfer(transferId: string, dto: DispatchTransferDto, userId: string)`:
   - Validates transfer exists and is in `PENDING_APPROVAL` status.
   - Inside `prisma.$transaction`:
     - For each line, locks and reads source store's `Inventory`:
       ```typescript
       // Check available stock >= line.requestedQty
       // Decrement availableQuantity by line.requestedQty
       // Increment inTransitQuantity by line.requestedQty
       // Increment version by 1
       // Record InventoryMovement: movementType = 'TRANSFER_OUT_DISPATCH'
       ```
     - Updates `StockTransfer` status to `APPROVED_IN_TRANSIT`, sets `dispatchedAt = now()`, `approvedBy = userId`, and attaches logistics details (`carrierName`, `vehicleNumber`, etc.).
3. `receiveTransfer(transferId: string, dto: ReceiveTransferDto, userId: string)`:
   - Validates transfer is currently in `APPROVED_IN_TRANSIT` status.
   - Inside `prisma.$transaction`:
     - For each line:
       - Decrements source store's `inTransitQuantity` by `line.requestedQty`.
       - Lazily gets or creates destination store `Inventory`.
       - Increments destination store `availableQuantity` by `line.receivedQty`.
       - Records destination `InventoryMovement: movementType = 'TRANSFER_IN_RECEIPT'`.
       - If `line.receivedQty < line.requestedQty` (Damage/Short-shipment shortfall):
         - Records discrepancy `InventoryMovement: movementType = 'DAMAGED_WRITE_OFF'`, `quantity: -(requestedQty - receivedQty)`, `remarks: 'In-transit shortfall/damage'`.
       - Updates `StockTransferLine` with `receivedQty`.
     - Updates `StockTransfer` status to `RECEIVED`, sets `receivedAt = now()`, `receivedBy = userId`.
4. `cancelTransfer(transferId: string, userId: string, reason: string)`:
   - If `PENDING_APPROVAL`: simply marks `status = 'CANCELLED'`.
   - If `APPROVED_IN_TRANSIT`: reverses source store inventory (decrements `inTransitQuantity`, increments `availableQuantity`, records `STOCK_ADJUSTMENT`), then sets `status = 'CANCELLED'`.
