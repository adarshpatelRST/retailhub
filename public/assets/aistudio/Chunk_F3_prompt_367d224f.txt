## 3. DETAILED IMPLEMENTATION SPECIFICATIONS

### A. API Layer (`src/modules/operations/inventory/api/inventory.api.ts`)
- `getInventory(params)`: Calls `GET /api/v1/inventory` with filters for `storeId`, `status`, `risk`, `search`, `page`, and `limit`.
- `getInventoryBalance(storeId, productId)`: Calls `GET /api/v1/inventory/${storeId}/${productId}`.
- `getMovements(storeId, productId, page = 1, limit = 20)`: Calls `GET /api/v1/inventory/${storeId}/${productId}/movements`.
- `adjustStock(dto)`: Calls `POST /api/v1/inventory/adjust` with `{ storeId, productId, quantityDelta, remarks, expectedVersion }`.
- `getTransfers(params)`: Calls `GET /api/v1/transfers` with status and store filters.
- `receiveTransfer(id, dto)`: Calls `POST /api/v1/transfers/${id}/receive` with `{ lines: [{ productId, receivedQty }], remarks }`.

---

### B. Summary Cards & Top Metrics (`components/InventorySummaryCards.tsx`)
- Renders 4 responsive cards using `RH_KPICard` / `DashboardCard`:
  1. **Total Inventory Value**: Calculated as sum of `(availableQuantity * costPrice)`. Formatted in Indian numbering (e.g., ₹18.4 Lakhs or ₹4.82 Cr).
  2. **Critical / Stock-Out SKUs**: Count of items where stock <= 0. Displayed with a red alert badge.
  3. **Low Stock SKUs**: Count of items where stock <= reorder level. Displayed with an amber warning badge.
  4. **Trapped Excess Capital**: Total value of surplus stock exceeding maximum thresholds. Displayed with a purple accent badge.

---

### C. Inward Receiving Scan (`components/ReceiveTransferModal.tsx`)
- State:
  - `scannedQuantities`: `Record<string, number>` mapping `productId` to scanned count.
  - `shortfallReasons`: `Record<string, string>` mapping `productId` to damage reason.
  - `barcodeInput`: string.
- Scanning Handler:
  - Text input for barcode with autofocus and camera/scanner icon.
  - On Enter / Scan: Matches barcode against line items. If matched, increments `scannedQuantities[item.productId]` by 1. Clears barcode input.
- Stepper Buttons:
  - Next to each item: `[ - ]` button (decrements count), direct numeric input, and `[ + ]` button (increments count).
- Shortfall & Damage Logic:
  - For any line where `scannedQty < line.requestedQty`:
    - Shows an amber warning box: `Shortfall: ${(line.requestedQty - scannedQty).toFixed(3)} units`.
    - Dropdown for reason: `"Damaged in Transit / Leaking"`, `"Missing / Short Shipped from Source"`, `"Expired / Unusable"`.
- Summary Panel:
  - Shows green text: `Units to Available Stock: ${totalReceived}`.
  - Shows red text: `Units to Damaged Write-Off: ${totalShortfall}`.
- Action: "Confirm Inward Receipt" button (calls `receiveTransfer` API and triggers Sonner success toast).

- Props: `isOpen: boolean`, `onClose: () => void`, `storeId: string`, `productId: string`, `productName: string`, `sku: string`.
- Renders responsive dialog (`sm:max-w-3xl`):

### E. Cycle Count Adjustment Modal (`components/AdjustStockModal.tsx`)
- Props: `isOpen`, `onClose`, `inventoryItem: InventoryRecord`.
- Displays current recorded stock and current `version`.
- Input fields:
  - `Adjustment Type`: "Add Stock" (+ delta) or "Reduce Stock / Write-off" (- delta).
  - `Quantity Delta`: Number input (`step="0.001"`).
  - `Projected New Stock`: Auto-calculated live (`Current + Delta`).
  - `Reason`: Dropdown (`"Physical Count Audit"`, `"Damaged Goods"`, `"Cashier Scan Variance"`, `"Other"`).
- Sends `expectedVersion = inventoryItem.version`. If conflict occurs (HTTP 409), displays Sonner error: *"Stock was updated by another transaction. Reloading current balance."*
