4. Risk & Status Classification:
   - Risk: `HIGH` (DOI <= 3.0), `MEDIUM` (3.0 < DOI <= 7.0), `LOW` (DOI > 7.0).

5. Target Transfer Horizon:
   - Calculate target units to bring destination to a 14-day operating buffer:

     `PostTransferDOI = (AvailableQuantity - TransferUnits) / ADS > 7.0 days`.

     `MaxSafeTransfer = Math.floor(AvailableQuantity - (7.0 * ADS))`.

8. Deduplication & Auto-Expiration:

### B. `DoiService` (`services/doi.service.ts`)
Implement pure mathematical and classification methods:
- `calculateDOI(availableQuantity: number, ads: number): number`:
  - Returns `999.0` if `ads <= 0 && availableQuantity > 0`.
  - Returns `0.0` if `availableQuantity <= 0`.
  - Returns `Number((availableQuantity / ads).toFixed(2))`.
- `classifyRisk(doi: number): 'HIGH' | 'MEDIUM' | 'LOW'`:
  - `doi <= 3.0` -> `'HIGH'`
  - `doi > 3.0 && doi <= 7.0` -> `'MEDIUM'`
  - `doi > 7.0` -> `'LOW'`
- `classifyStatus(availableQuantity: number, reorderLevel: number, maximumStock: number, doi: number): 'CRITICAL' | 'LOW' | 'HEALTHY' | 'EXCESS'`:
  - `availableQuantity <= 0` -> `'CRITICAL'`
  - `availableQuantity <= reorderLevel` -> `'LOW'`
  - `availableQuantity > maximumStock || doi > 30.0` -> `'EXCESS'`
  - Otherwise -> `'HEALTHY'`

### C. `CandidateRankingService` (`services/candidate-ranking.service.ts`)
Implement donor discovery and scoring:
- `calculateDistance(lat1: number, lon1: number, lat2: number, lon2: number): number`:
  - Implements standard Haversine formula returning kilometers. If coordinates are missing on either store, returns default distance of `999.0` km.
- `findAndRankCandidates(destStoreId: string, regionId: string, productId: string, targetUnitsNeeded: number)`:
  - Queries active stores where `regionId == regionId AND id != destStoreId AND isActive == true`.
  - For each store:
    - Reads `Inventory` for `productId`. If stock <= minimumStock, skip.
    - Gets rolling ADS from `VelocityService`.
    - Computes `currentDOI = DoiService.calculateDOI(stock, ads)`.
    - If `currentDOI <= 30.0` (not excess), skip.
    - **Enforce 7-Day Protection**:
      - `maxSafeTransfer = Math.floor(availableStock - (7.0 * ads))`.
      - If `maxSafeTransfer <= 0`, skip.
      - `transferUnits = Math.min(targetUnitsNeeded, maxSafeTransfer)`.
      - `postTransferDOI = (availableStock - transferUnits) / ads`.
    - Computes distance from destination store using Haversine.
  - Normalizes excess stock qty and excess DOI across pool.
  - Computes `suitabilityScore = (normQty * 60) + (normDOI * 40)`.
  - Sorts candidates:
    1. Primary sort: `suitabilityScore DESC`.
    2. Primary tie-breaker: `distanceKm ASC` (shortest distance wins).
    3. Secondary tie-breaker: `availableStock DESC`.
  - Assigns `rank = 1, 2, 3...` and returns `CandidateStoreDto[]`.

### D. `RebalanceService` (`services/rebalance.service.ts`)
Main orchestrator handling business logic, deduplication, auto-expiration, and DB persistence:
- `evaluateStore(storeId: string)`:
  - Fetches store details and all active inventories.
  - For each inventory record:
    - Fetches rolling 30-day ADS from `VelocityService`.
    - Calculates DOI, risk, and status.
    - **Auto-Expiration Check**:
      - If status == `'HEALTHY'`, check if an existing recommendation with `storeId == storeId AND productId == productId AND status IN ('OPEN', 'MODIFIED')` exists.
      - If found, update `status = 'AUTO_EXPIRED'`, `reason = 'Auto-closed: Destination store stock normalized to healthy buffer via inward receipt.'`.
    - **Stock-Out Rebalance Trigger**:
      - If risk == `'HIGH'` (DOI <= 3.0):
        - Compute target units: `targetUnitsNeeded = Math.ceil((14.0 * ads) - availableStock)`. If targetUnitsNeeded <= 0, default to 10.
        - Call `CandidateRankingService.findAndRankCandidates(...)`.
        - If candidates exist:
          - Select `Rank 1` candidate as `fromStoreId`.
          - Prepare transfer qty: `recommendedQuantity = Math.min(targetUnitsNeeded, candidate.maxSafeTransferQty)`.
          - Set `recType = 'STOCK_TRANSFER'`.
          - Prepare evidence array:
            - `DEST_DOI`: destination DOI
            - `DEST_STOCK`: current stock
            - `SRC_DOI`: donor DOI
            - `SRC_STOCK`: donor stock
            - `SRC_POST_TRANSFER_DOI`: projected donor DOI
            - `DISTANCE_KM`: distance between stores
        - If NO candidates exist in region:
          - Set `recType = 'REORDER'`, `fromStoreId = null`.
          - Set `recommendedQuantity = targetUnitsNeeded`.
          - Prepare evidence: `REASON: 'No regional store holds surplus inventory. Central Supply reorder required.'`
        - **Deduplication Check**:
          - Query `Recommendation` for existing record where `storeId == storeId AND productId == productId AND status IN ('OPEN', 'MODIFIED')`.
          - If exists:
            - Update existing record: `recommendedQuantity`, `fromStoreId`, `updatedAt = now()`.
            - Overwrite child `RecommendationEvidence` with refreshed metrics.
          - If not exists:
            - Insert new `Recommendation` (generate unique `recommendationNumber = 'REC-' + Date.now().toString().slice(-6))`.
            - Insert child `RecommendationEvidence` rows.
  - Returns `EvaluationResultDto`.
- `evaluateRegion(regionId: string)`: Iterates over all stores in region and aggregates results.
- `evaluateEnterprise()`: Iterates over all active stores in system and aggregates results.
- `@Cron('0 6 * * *') handleMorningRebalance()`: Automatically runs `evaluateEnterprise()` every morning at 06:00 AM.
- `evaluateSingleSku(storeId: string, productId: string)`: Asynchronous method triggered by POS checkout threshold breach.
