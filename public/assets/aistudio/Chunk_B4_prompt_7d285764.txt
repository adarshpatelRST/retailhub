## 3. DETAILED IMPLEMENTATION SPECIFICATIONS

### A. Sales Core Module (`src/modules/sales/`)

1. **DTOs**:
   - `CreateSaleLineDto`:
     - `productId`: UUID string.
     - `quantity`: number (min 0.001).
     - `unitPrice`: number (min 0).
     - `discount`: optional number (default 0.00).
     - `netAmount`: number (min 0).
   - `CreateSaleDto`:
     - `transactionNumber`: string (unique POS invoice code, e.g. "POS-BPL-20261022-0001").
     - `storeId`: UUID string.
     - `transactionDate`: optional ISO Date string (defaults to now).
     - `customerId`: optional string (phone/loyalty number).
     - `lines`: array of `CreateSaleLineDto` (min 1 item).
   - `BatchSalesDto`:
     - `transactions`: array of `CreateSaleDto` (min 1, max 500).
   - `SalesQueryDto`:
     - `page`: optional number (default 1).
     - `limit`: optional number (default 20).
     - `storeId`: optional UUID string.
     - `startDate`: optional ISO Date string.
     - `endDate`: optional ISO Date string.

2. **`SalesService` (`sales.service.ts`)**:
   - `createSale(dto: CreateSaleDto)`:
     - Runs inside `prisma.$transaction`.
     - Validates unique `transactionNumber` (throws `ConflictException('SALES_DUPLICATE_TX')` if exists).
     - Computes `totalQuantity = SUM(lines.quantity)` and `totalAmount = SUM(lines.netAmount)`.
     - Inserts `SalesTransaction` and child `SalesTransactionLine`s.
     - For each line item:
       - Finds or lazily creates `Inventory` for `(dto.storeId, line.productId)`.
       - Decrements `availableQuantity` by `line.quantity`.
       - Increments `version = version + 1`.
       - Inserts immutable `InventoryMovement`:
         `movementType: 'POS_SALE'`,
         `quantity: -line.quantity`,
         `referenceType: 'SALES_TRANSACTION'`,
         `referenceId: transaction.id`,
         `createdBy: 'POS_TERMINAL'`.
     - Returns created transaction with lines.
   - `createBatch(dto: BatchSalesDto)`:
     - Iterates through `dto.transactions` and executes each sale sequentially or in chunked transactions.
     - Returns `{ processedCount: number, successfulTxNumbers: string[] }`.
   - `findAll(query: SalesQueryDto, dataScope?: any)`:
     - Merges query filters with `dataScope` (Store Managers restricted to their assigned store).
     - Returns `PaginatedResponse<SalesTransaction>` with line items and product details.
   - `getSummary(storeId?: string, startDate?: Date, endDate?: Date)`:
     - Aggregates total revenue, total units sold, total transaction count, and average basket value.

3. **`VelocityService` (`velocity.service.ts`)**:
   - `getAverageDailySales(storeId: string, productId: string, windowDays: number = 30)`:
     - Calculates:
       ```typescript
       const cutoffDate = new Date();
       cutoffDate.setDate(cutoffDate.getDate() - windowDays);

       const result = await this.prisma.salesTransactionLine.aggregate({
         where: {
           productId,
           salesTransaction: {
             storeId,
             transactionDate: { gte: cutoffDate },
           },
         },
         _sum: { quantity: true },
       });

       const totalQty = Number(result._sum.quantity || 0);
       const ads = totalQty / windowDays;
       return Number(ads.toFixed(3)); // Returns 0.000 if no sales
       ```
   - `getStoreVelocityMap(storeId: string, windowDays: number = 30)`:
     - Returns a Map/Dictionary of `{ [productId]: averageDailySales }` for all products sold in that store over the window, using a single `groupBy` aggregation query on `SalesTransactionLine`.

4. **`SalesController` (`/api/v1/sales`)**:
   - `POST /api/v1/sales`: Protected by `JwtAuthGuard`. Ingests single POS receipt.
   - `POST /api/v1/sales/batch`: Protected by `JwtAuthGuard`. Ingests bulk receipts.
   - `GET /api/v1/sales`: Protected by `JwtAuthGuard`, `DataScopeGuard` with `@DataScope('store')`.
   - `GET /api/v1/sales/summary`: Returns aggregate KPIs.
   - `GET /api/v1/sales/velocity/:productId`: Query parameter `?storeId=&windowDays=30`. Returns ADS velocity.
